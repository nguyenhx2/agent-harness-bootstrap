# Benchmark: v1.20.0 against v1.19.3

Both runs are `python benchmark/benchmark.py` at each tag, with no API key, so token figures are
estimated at 3.6 characters per token and byte figures are exact. The table is parsed from the two
outputs below by the script that wrote this file; nothing in it is typed by hand. Commit hashes and
wall-clock timings are replaced with placeholders so the file does not change from run to run.

The v1.19.3 column for the simulated mission and the task resume shows the same harness with the
new mechanism switched off, because v1.19.3 has neither a verification ledger nor `task.py`.

| Measure | v1.19.3 | v1.20.0 | Change |
|---|---:|---:|---:|
| Baseline A: known-bad payloads blocked | 29 | 67 | +131% |
| Unconditional rule bytes (every session) | 28,821 | 23,047 | -20% |
| Share of rule content kept out of the default session (%) | 68 | 73 | +7% |
| Always-loaded bytes, full profile | 36,800 | 31,179 | -15% |
| Always-loaded bytes, lean profile | 32,964 | 27,308 | -17% |
| Guarded flow steps that run the full suite | 1 | 1 | +0% |
| Simulated mission: review and suite runs | 17 | 11 | -35% |
| Resume a 40-row task: bytes read | 8,253 | 966 | -88% |

What this does not measure: whether agents write better code, task success rate, or time to a
correct change. Baseline A grew because the eval grew; a higher block count means more attack
shapes are covered, and the must-allow cases (not counted here) keep it honest.
