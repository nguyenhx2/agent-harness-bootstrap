# Agent Harness - プレゼンテーション構成案

[English](PRESENTATION-OUTLINE.md) · **日本語**

**この講演を一行で:** AI エージェントに、本当に理解できるリポジトリと、抜け出せないハーネスを与える。
**リポジトリ:** [agent-harness-bootstrap](https://github.com/nguyenhx2/agent-harness-bootstrap)
**スライド:** `presentation/index.html` - 23 枚、EN / VI / JA。この構成案にセクション単位で沿っています。
スライドはこの台本のビジュアルであって、もう一つの写しではありません。主張が変わったら、両方を変えてください。
**所要時間:** 40 分 (講演 28 分 + デモ 8 分 + 質疑応答)。短縮版と拡張版は末尾にあります。

---

## 全体の流れ

> エージェントが失敗するのは、リポジトリを理解していないか、止めるものが何もないからだ →
> それが現れる 9 つの場所 → 解決策はより良いプロンプトではなくハーネス →
> 2 つのスキルが、リポジトリの目的に合った規模でそれを組み立てる → 3 つの仕組みがそれを機能させ続ける →
> 実際に動かしてみる → 数字はこうなる。

まず考え方、次に痛み、最後に製品。デモは後半に置きます。何を見ればよいかを聴衆が分かってからです。

## 0. 考え方 (2 分) - スライド 1-2

何よりも先に、二つの半分を言います。この後のすべては、そのどちらかです。

| 半分 | リポジトリの中で意味すること |
|---|---|
| **本当に理解できるリポジトリ** | 安定した ID を持つ書かれた契約。リポジトリの目的に合った規模のチーム。適用されるときだけ読み込まれるルール。ディスク上のタスク状態。だからウィンドウを閉じても何も失われない |
| **抜け出せないハーネス** | ツールが実行される前に終了コード 2 で止めるフック。拒否リスト、席ごとのツール許可リスト、エージェントが生成できる深さの上限。どれもモデルの同意を求めない |

**決めの一言:** *「問題はモデルが賢くないことではありません。モデルの周りが何も設計されていないことです。」*

## 1. どこで壊れるか (5 分) - スライド 3-4

3 つの場所に 9 つの問題。番号を振っておきます。答えが出るたびに、その番号が戻ってきます。

| 場所 | 何が壊れるか |
|---|---|
| **セットアップ** | 01 キットは全部をインストールし、何にも合わない · 02 プロンプトの言い回しに時間を取られる · 03 ウィンドウがどれだけ大きくても、コンテキストは有限 |
| **制御** | 04 指示として書かれたルールは飛ばせる · 05 ハルシネーションとあふれがプロセスを脱線させる · 06 モデルが違えば出力が不安定 |
| **プロジェクト** | 07 リポジトリごとに独自の標準と目的がある · 08 チャットを閉じるかクラッシュすると、作業も一緒に消える · 09 エージェントが組み立てられる仕様を書くチームは少ない |

**人間の側に時間を割く** (ほとんどの聴衆は、この枠組みで聞いたことがありません): 不安定さはモデルだけの
ものではありません。プロンプトの書き方は標準化されておらず、自然言語は情報が欠けるインターフェースで、
どう頼んだかは git に残らず、引き継ぎのたびに新しい翻訳が起きます。ハーネスを通すと、自由形式の言葉が
入ってくるのは**一度だけ**、インテークの時点で、それが契約になります。それ以降の引き継ぎはすべてファイルです。
*「人により良いプロンプトを書かせようとしているのではありません。プロンプトがインターフェースであることを
やめさせようとしているのです。」*

引用のスライドで締めます: *速さが優位を生み、制御が目的地まで連れていく。*

## 2. ハーネスはエージェントのオペレーティングシステム (2 分) - スライド 5

エージェント = アプリケーション、ハーネス = オペレーティングシステム、SDK = 構成部品、モデル = CPU。
フレームワークでは開発者がオーケストレーションを書きます。ハーネスでは計画を立てるのはモデルで、
ハーネスはそれを軌道に乗せ続けます。3 つの仕組みを予告します: **コンテキスト**、**オーケストレーション**、
**セキュリティ**。

## 3. 2 つのスキル、それぞれの半分に一つ (4 分) - スライド 6-7

| スキル | 生み出すもの | 解消する問題 |
|---|---|---|
| **`spec-builder`** | 選択式の仕様セット (コア 6 セクション、任意は最大 8): 安定した ID、受け入れ基準、データモデル、必須のセキュリティ NFR | 09, 02 |
| **`harness-bootstrap`** | `.claude/`: リポジトリの目的に合った規模の席の構成、対象パス限定のルール、フック、拒否リスト、ディスク上のタスクボード | 01, 04, 08 |

最初に選ぶ 4 つのモード: **Greenfield**、**Brownfield** (コードベース分析は必須で、最初に行う)、
**Audit** (読み取り専用。修正は人が適用する)、**Update** (既存の `vars.json` に対して再実行する。
再ブートストラップは決してしない)。既存のファイルは突き合わせられ - `ADDED` / `KEPT` / `CONFLICT` -
上書きされることはありません。

**目的プロファイル**が 01 と 07 に答えます。インテークの最初の質問は、このリポジトリが何のためにあるかです:

| 目的 | 席 | 検証の方法 |
|---|---|---|
| コード | 実在するモジュールごとに dev エージェント 1 つ、レビューゲート、`spec-guardian`。求められればテストとデータベースの席 | テストとコードレビュー。セキュリティレビューは差分がそれに値するときだけ |
| 調査 | `researcher`、`checker` | すべての主張を、それを述べている出典まで辿る |
| 戦略 | `strategist`、`researcher`、`checker` | 区別できる選択肢、採点前に固定した基準、結論を覆す前提 |
| ドキュメント | `writer`、`checker` | 出典に対して正確で、リンクが解決すること |

目的は組み合わせられ、コード以外のすべての目的を一つの `checker` が受け持ちます。コード専用の選択肢は
コードの目的がなければ拒否されるので、することのない席が置かれることはありません。

**決めの一言:** *「何かを書く前に、あなたのコードを読みます。汎用のテンプレートは、正しく見えながら
誰か別の人のリポジトリを説明してしまうからです。」*

## 4. スキル: 探す、作る、つなぐ (2 分) - スライド 8

- **探す** - 探索はマニフェストを読み、スタックに合うスキルだけを検索し、チェックを入れる前に
  それぞれのファイルを読みます。知らないうちにインストールされるものはありません。
- **作る** - `/new-skill` はまず、そのワークフローがそもそもスキルであるべきかを判断し (断るのは普通の
  結果です)、テンプレートから雛形を作り、トリガーケースを書き、`skill-check.py` で lint します。
- **つなぐ** - `/skill-wire` は、そのスキルを席の frontmatter の `skills:` プリロードに追加します。
  ディスク上にあってもつながっていないスキルは、`harness-view` が報告します。

## 5. 仕組み A: コンテキスト (5 分) - スライド 9-11

**要点:** コンテキストウィンドウは RAM、作業はディスクに住み、圧縮 (コンパクション) は設計上、
生き延びられる前提です。03、05、08 に答えます。

| 階層 | そこにあるもの | 圧縮で何が起きるか |
|---|---|---|
| **常時 RAM** | `CLAUDE.md`、7 つの無条件ルール、エージェント本体、ツールスキーマ | 毎ターン再注入されるので残る |
| **遅延 RAM** | 10 の対象パス限定ルール | 一致するファイルに触れると再読み込みされる |
| **ディスク** | ボードとタスクごとのファイル: チェックポイントと上限付きのセッションログ | 何も起きない。コミット済みの markdown だから |
| **アーカイブ** | 終了したサブエージェントの実行ごとに 1 ファイル。`SubagentStop` フックが書く | 何も起きない。事後に書かれるから |

これを慣習ではなく仕組みにしているのは、次の 3 つです:

1. **タスク状態の書き手は一人だけ。** `task.py move` がボードの行、ファイルの `status:`、そのフォルダを
   まとめて変え、その後で行を読み戻します。ボードを手で編集すると `guard-board` がブロックします。
2. **再開時に読むのは履歴ではなく 3 行。** チェックポイントには次の一手、最後にグリーンだったコミット、
   未解決の質問が入っています。セッションログは最新の行だけをファイルに残し、残りは隣のコミット済み
   アーカイブにまとめます。
3. **完了とクラッシュはファイルで見分ける。** 締めの処理が `MISSION COMPLETE` を書きます。長期の
   プロジェクトでは、`compact-checkpoint` が圧縮の前に状態を書き、`session-context` が圧縮の後で
   進行中のタスクをエージェントの目の前に戻します。

**決めの一言:** *「ウィンドウが閉じるのは事故ではありません。想定どおりのケースです。」*

## 6. 仕組み B: 変更に比例したプロセス (6 分) - スライド 12-14

**ルーティングの段階 (ティア)** は、何かを割り当てる前に決まります。ほとんどの変更は Inline か Direct です。

| 段階 | 変更の内容 | 誰が実行するか |
|---|---|---|
| **Inline** | 質問、調べもの、ドキュメントや設定の編集、全体が見渡せる修正 | メインセッション。サブエージェントなし |
| **Direct** | 1 モジュール、元に戻せる、契約・スキーマ・認証・決済・インフラに触れない | 担当エージェントを直接呼ぶ。タスクファイルなし |
| **Standard** | 1 ドメインで複数ファイル、または番号付きの要件 | 担当エージェント。圧縮を越えて残す必要があるときだけタスクファイル |
| **Guarded** | 2 つ以上のドメイン、またはスキーマ、認証、お金、公開契約、マイグレーション、デプロイ、個人データ | オーケストレーターを通る唯一の段階 |

生成の深さと同時実行のサブエージェント数は `settings.json` の env で上限が決まっているので、
ファンアウトが暴走することはありません。*「変更に必要な段階より重い段階を選ぶのは、慎重さではなく欠陥です。」*

**比例した検証。** `verify-plan.py` は差分が触れたパスを読み、必要なゲートを表示します。
飛ばしたゲートは、理由と一緒にそれぞれ 1 行ずつ記録されます。

| 差分が触れるもの | 実行されるもの |
|---|---|
| 何であれ | シークレットスキャン。決して飛ばさない |
| ドキュメントか設定だけ | レビュアーの席なし、テスト実行なし |
| コード | それに触れるテストとコードレビュー。全スイートはブランチのゲートで一度だけ |
| 認証、シークレット、パース、データ、AI のツール呼び出し、依存関係、インフラ | セキュリティレビューも |
| 名前の付いた重要フロー | そのフローの end-to-end 実行。既定では決して走らない |

**Guarded のフロー:** オーケストレーター (分析、分解、登録) → 範囲を限った dev の席 → プルリクエストの前に、
ブランチの差分に対するゲートを一度。レビュアーは `Edit` も `Write` も持ちません。ゲートが通るのは、
セッションログがその実行を記録しているときだけです: *エージェントの「完了しました」は、検証すべき主張です。*
strict のフックセットでは、証拠のない完了宣言を `stop-evidence` が一度だけ差し戻します。

## 7. 仕組み C: セキュリティ (5 分) - スライド 15-17

**要点:** 多層防御。そしてモデルに投票権はありません。04 と 06 に答えます。

| 層 | 止めるもの |
|---|---|
| 1. 拒否リスト | **見えない**もの: `.env`、鍵、`secrets/`、`git push --force`、`rm -rf` |
| 2. フック、終了コード 2 | **できない**こと |
| 3. ツール許可リスト | **届かない**もの: 判定役は `Edit` を持たず、`Agent` を持つのはオーケストレーターだけ |
| 4. `maxTurns` と生成の上限 | 暴走するループやファンアウト |

弱点は自分から言います: 拒否リストは前方一致で、並べ替えれば回避できます。それは減速帯です。
**ゲートはフックです。**

**あらゆるイベントにフック**。それぞれ `.sh` と `.ps1` の系統があり、それを必要とするオプションのときだけ
同梱されます (全体の表は `harness-bootstrap/assets/claude/hooks/README.md` にあります):

| いつ | 何を捕まえるか | どうするか |
|---|---|---|
| ツール呼び出しの前 | シークレット、main へのコミット、Accepted の ADR、構成外の席の生成、ボードの手編集、破壊的なコマンド (ルートでの `rm -rf`、保護ブランチへの force push、`git reset --hard`)、リポジトリにデータベースがあるときは出荷済みのマイグレーション。オプトインの strict セットでは、未知のホストへのアップロード、大きなファイル、ロックファイルの編集、`curl \| sh` が加わる | ブロックする |
| 失敗の後 | 同じ失敗する呼び出しの繰り返し | 警告し、それからブロックする |
| 停止の前 | 裏付けのない「すべてのテストが通りました」 | 一度だけ差し戻す |
| 圧縮の前後 | 前にチェックポイント、後に進行中のタスクを戻す | 決してブロックしない |
| 編集の後 | 変更された仕様、古くなったグラフ、壊れたリンク、出典のない調査の主張 | 知らせる |

**この講演で最も強い主張:** `eval/guardrail_eval.py` は本物のハーネスを雛形から作り、フックの系統ごとに
250 のペイロードを撃ち込みます: 101 must-block、149 must-allow、250/250 正解。対象は strict のフック、
長期セッション用のフック、データベースのガードを有効にした (`hooks_strict`、`long`、`db`) ハーネスです。
モデルには一切問い合わせません: ガードレールはシェルスクリプトなので、結果がモデルに左右されることは
ありえません。*「安いモデルでもシークレットはコミットできません。モデルが分別をわきまえているからでは
なく、フックが終了コード 2 を返し、ツール呼び出しがそもそも起きないからです。」* そのうえで正直な限界を:
これは床であって、天井ではありません。

## 8. コストと、frontmatter の残り (3 分) - スライド 18

**要点:** 高くつく構成は、選ばないことで手に入る構成です。

- **席ごとのモデルと effort。** 判断とゲートには Opus、契約に沿った作業には Sonnet、機械的な席には Haiku。
  契約が固まっているところでは effort を low や medium に。
- **frontmatter の残りも意図して設定する。** すべての判定役に `disallowedTools`、ゲートがプロンプトで
  止まらないよう `permissionMode`、レビュアーには `omitClaudeMd`、`memory` はリポジトリを学ぶ席だけ。
- **現行モデル向けに書かれた指示。** 「再確認せよ」「最終確認せよ」といった指示は入れません - 現行モデルは
  自分の作業を検証するので、確認はゲートに一度だけ置きます。席が何を委任してよいかは明示的に制限します。

`benchmark/model_cost.py` によるモデル化: 既定の構成は 1 機能あたり $2.523 で、すべてを Opus の xhigh にした
場合より 32% 安くなります。「モデル化した」と言い、「測定した」とは決して言わないこと。

## 9. 1 つのハーネス、3 つのツール (2 分) - スライド 19

ルールは `.cursor/rules/*.mdc` と `AGENTS.md` に移植され、強制は `.cursor/hooks.json` (アダプター付き) と
`.codex/hooks.json` に移植されます。3 つとも、シークレットの読み取りと main へのコミットをブロックします。

## 10. 本当につながっているか (2 分) - スライド 20

`tools/harness-view` は、モデルを介さずにディスク上にあるものを読みます:

- **どんなハーネスでも読む** - コードのリポジトリも、調査や執筆のリポジトリも、orchestrator-kit の
  インストールも。文書化されているすべての frontmatter フィールド。あらゆるイベントのフックを、
  `settings.json` からも、席自身の `hooks:` からも。
- **評価 (Assess)** - すべての指摘はそのノードにリンクします: モジュールのない席、登録されていないフック、
  ボードの行とファイルが食い違うタスク (`DRIFT` と表示)。
- **編集** - ルール、フック、席を退避させる (`.claude/disabled.json` に記録。レビュアーを止めるには
  確認フレーズの入力が必要)、コマンドの手順を並べ替える、席のモデル、effort、ツールを設定する。

## 11. ライブデモ (8 分) - 予備としてスライド 21

既存のコードがある実際のリポジトリを使います。Brownfield は説得力があり、空のフォルダにはありません。

1. **(30 秒)** 適用前のリポジトリ: ソースはあるが `.claude/` はない。
2. **(90 秒)** `/harness-bootstrap`: まずコードを読み、目的を尋ね、すべての席のモデルと effort を含む
   計画を見せる。この時点ではまだ何も書かれていない。
3. **(30 秒)** 承認する。実行の所要時間を読み上げる (~0.2s)。
4. **(2 分)** **わざと壊す** - `cat .env`、`main` へのコミット、Accepted の ADR の編集。
   すべてブロックされる。講演全体がこの瞬間のために組み立てられています。
5. **(90 秒)** `python eval/guardrail_eval.py` をその場で。*「モデルには一切問い合わせていません。
   これは終了コードです。」*
6. **(60 秒)** ドキュメントだけの変更に `python .claude/scripts/verify-plan.py`: シークレットスキャンだけで、
   他には何も走らない。
7. **(60 秒)** 新しいセッションで `/task-resume`: チェックポイントを読み、タスクの途中から再開する。

予備の手順: ツールが動かない → クリップ 4、次にギャラリー。時間が足りない → 6 と 7 を削る。
**4 と 5 は決して削らない**。

## 12. 証拠 (3 分) - スライド 22

すべての数字はスクリプトから出ており、文書がずれると `scripts/check_numbers.py` が CI を失敗させます。

| 指標 | 前 | 後 | 変化 |
|---|---:|---:|---:|
| Read path (bytes pulled into context) - コンテキストに読み込むバイト数 | 234,196 | 178,719 | -24% |
| Read path (files read) - 読み込むファイル数 | 24 | 10 | -58% |
| Write path (bytes the model must author) - モデルが書くべきバイト数 | 95,064 | 9,439 | -90% |

- ルール本文の 73% が既定のセッションに入らない
- ガードレール評価 250/250 (`hooks_strict`、`long`、`db` を有効化)、モデルへの問い合わせなし
- 雛形の生成は ~0.2s、再実行するとすべてのファイルが `KEPT` と報告される

バイト数は厳密な値です。トークンとコストの数字は、1 トークンあたり 3.6 文字としてモデル化しています。

## 13. 締め (2 分) - スライド 23

エージェントはリポジトリを理解している。ハーネスからは出られない。作業は変更に比例して確認される。

```
/spec-builder           # まず契約を書く
/harness-bootstrap      # このリポジトリ用のハーネスを組み立てる
```

## 質疑応答の準備

| 質問 | 短い答え |
|---|---|
| *Claude Code に縛られますか?* | いいえ。強制込みで Cursor と Codex に移植できます。`AGENTS.md` はベンダー中立の契約です |
| *すでに `.claude/` フォルダがあります。* | 突き合わせるだけで、上書きはしません。違いは `CONFLICT` として返ってきます |
| *うちのリポジトリはコードではなく調査です。* | 目的プロファイル: 調査のリポジトリには `researcher` と `checker` が付き、出典で検証されます。テストやコードレビューの席はありません |
| *エージェントはフックを回避できますか?* | 拒否リストは回避できます。それは減速帯です。フックはツールが実行される前に発火し、終了コード 2 で止めます |
| *安いモデルにすると安全性が崩れますか?* | いいえ: モデルには問い合わせず、ガードレールはシェルスクリプトなので、結果はモデルに左右されません。コードの品質とレビューの深さは下がります |
| *開発者の作業が遅くなりませんか?* | 小さな作業では遅くなりません。Inline と Direct はオーケストレーターもタスクファイルも飛ばし、ドキュメントの変更にはレビュアーがまったく付きません |
| *ただの大きな CLAUDE.md では?* | CLAUDE.md は、圧縮の後でモデルが忘れるかもしれない助言です。これは強制と、永続する状態です |
| *ポリシーの判断は誰が持つのですか?* | あなたです。ガバナンスのルールは空欄のまま出荷されます。スキルがライセンス方針や分類表をでっち上げることはありません |
