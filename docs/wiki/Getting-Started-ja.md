# はじめに

[[English|Getting-Started]] · **日本語**

## インストール

[最新リリース](https://github.com/nguyenhx2/agent-harness-bootstrap/releases/latest) からバンドルを
ダウンロードし、スキルのディレクトリに展開します:

```bash
unzip agent-harness-bootstrap.zip -d ~/.claude/skills/
```

あるいはダウンロード自体を省略できます。推奨はプラグインマーケットプレイスで、任意の
Claude Code セッションの中で次を実行します:

```text
/plugin marketplace add nguyenhx2/agent-harness-bootstrap
/plugin install harness-bootstrap@agent-harness-bootstrap
/plugin install spec-builder@agent-harness-bootstrap
```

以後の更新は `/plugin update` で届きます。zip はオフラインでバージョンを固定したいときの経路として残ります。

Claude Code は次のセッションからスキルを認識します。各アーカイブはスキルのディレクトリ内に
`VERSION` ファイルを持っているので、インストール済みのスキルは自分が何者かを示せます。手元に何が
入っているか分からなくなったら、`~/.claude/skills/harness-bootstrap/VERSION` を読んでください。

## どちらのスキルを先に使うか

どちらが面白そうかではなく、すでに手元に何があるかで決まります。

| あなたの状況 | 実行するもの |
|---|---|
| アイデア、書き起こし、メモ、あるいはレガシー文書の山があり、仕様はない | まず `/spec-builder`、次に `/harness-bootstrap` |
| 既存のコードベースがある (仕様の有無は問わない) | `/harness-bootstrap` - まずコードを読みます |
| 分析はするが決して変更してはならないリポジトリ | `/harness-bootstrap` で、監査専用だと答える |

どちらのスキルも、もう一方を必要としません。契約はハーネスをより良くし、ハーネスは契約を強制
可能にしますが、それぞれ単独で成り立ちます。

## harness-bootstrap を実行すると何が起きるか

**1. まずコードを読みます。** ソースが少しでもあるリポジトリでは、分析は任意ではなく必須です。
棚卸しレポート (Inventory Report) - スタック、モジュール、観察した規約、見つけた危険な操作、そして
不足 - を作り、何かを書き込む前にあなたに見せます。以降のすべては、このレポートの結果で
パラメータ化されます。

**2. コードでは決められないことを尋ねます。** 最初の質問は、そのリポジトリが何のためのものか
(コード、調査、戦略、ドキュメント、任意の組み合わせ) です。以降の質問は、その目的が必要とする
場合にだけ尋ねます。続いて、ドキュメントの言語、コミットの名義、データの機微度、どの操作を
ゲートすべきか、プロジェクトがどれくらい長く続くか、テストを自動化したいか。選択式の質問は、
回答をあらかじめ埋めた一つの質問票にまとめられ、呼び出しは最大二回、あなたが書く言語で行われます。
分析ですでに答えが出ている項目は、改めて尋ねません。まだ仕様がなければ、不足を記録するだけで
なく `spec-builder` に引き継ぎます。

**3. 書き込む前に計画を見せます。** 何を作り、何を残し、何を変更するか、そして各席のモデルと
effort を含む編成。あなたが承認するか、変更します。

**4. 足場を組みます。** スキャフォルダは**既存のファイルを決して上書きしません**。各ファイルを
`ADDED`、`KEPT` (すでに同一)、`CONFLICT` (存在し、内容が異なる) のいずれかで報告します。`CONFLICT` は
エラーではありません。突き合わせの待ち行列であり、一件ずつ手で解決します。見つけた各モジュールに
短い `CLAUDE.md` も書き、最後に席、フック、ルール、コマンドの間のすべてのリンクが解決できるかを
確認します。

**5. 要約と次の一歩が示されます。** 通常は `/task-resume`、仕様がまだなければ `spec-builder` です。

## 最初のループ

ループを一度回すまで、ハーネスは完成していません。実際のタスクを一つ作り、ボードに登録して、
再開します:

```bash
/new-task          # 質問してから docs/tasks/active/TASK-001.md を書き、master-plan.md に登録する
/task-resume       # タスクのチェックポイントを読み、次のステップから再開する
/review-changes    # PR を開く前のレビューゲート
```

`/new-task` は、合意した作業についてだけ、しかもあなたが承諾した後にだけタスクを開きます。それ以降、
タスクの状態は `python .claude/scripts/task.py` を通して変わり、ファイル、そのフォルダ、ボードの行を
揃えたまま保ちます。ボードの行を手で編集しようとすると拒否されます。`/task-resume` が何も
見つけなければボードは空で、それ自体が答えです。ブラウンフィールドのリポジトリでは、分析が不足の
一覧からボードを埋めるので、初日から実際の作業が待っています。

## 本当に守っているか確かめる

ガードレールを鵜呑みにしないでください。リポジトリから次を実行します:

```bash
python eval/guardrail_eval.py
```

実際のハーネスを (strict フック、長時間セッション用フック、データベースガードを有効にして) 組み立て、
既知の悪いペイロードと既知の良いペイロードを、フックの系統ごとに撃ち込みます。モデルには問い合わせ
ません。CI が実行するのも同じコマンドです。ハーネスがもたらす違いを見たいなら、`benchmark.py` が
must-block のペイロードを、ハーネスのあるリポジトリと、同じリポジトリから `.claude/` を取り除いたものの
両方に撃ち込みます。ハーネスが整合しているかを確かめるには、自分のリポジトリで
`python .claude/scripts/harness-check.py` を実行してください。何も指していないリンクがあれば、その
ファイルと行を示します。

## 取り除く

```bash
rm -rf .claude/
```

すべての部品はファイルです。デーモンもサービスもなく、リポジトリの外に片付けるものは何もありません。
これは意図的です。コマンド一つで削除できないハーネスは、評価もできないハーネスです。
