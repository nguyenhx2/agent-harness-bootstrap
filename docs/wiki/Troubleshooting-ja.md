# トラブルシューティング

[[English|Troubleshooting]] · **日本語**

ここにある項目はどれも、仮定の話ではなく、実際に起きた失敗です。

## フックが何もブロックしない

**まず系統を確認します。** Windows 向けのハーネスは `.ps1` のフックを同梱します。`settings.json` が
`.sh` のコマンドを登録していると、検索はフックを見つけられず、すべてを飛ばし、何に対しても許可を
返します。その間もコマンドは「ブロックした」と表示します。これは一度、実際に出荷されました。

```bash
harness-view assess .        # 同梱されているのに登録されていないフックを報告する
```

系統と登録は、まさに食い違わないようにするために、どちらも一つのフラグから導かれます。食い違って
いるなら、そのハーネスは手で編集されています。

**次に、フックを直接テストします。** フックは標準入力で JSON を読み、終了コードで答えます:

```bash
echo '{"cwd":"'"$PWD"'","tool_name":"Bash","tool_input":{"command":"cat .env"}}' \
  | bash .claude/hooks/protect-secrets.sh; echo "exit=$?"
```

`2` はブロックした、`0` は許可したという意味です。PowerShell では `$?` ではなく必ず `$LASTEXITCODE` を
確認してください。`$?` は真偽値で、スクリプトが実行されたことを示すだけで、何を判定したかは
示しません。

## `guard-agent-spawn` にディスパッチを拒否される

このフックは検証台帳 (`.claude/state/verify-ledger.jsonl`) を読みます。すでに合格した内容に対する
レビューやスイートの実行、結果が記録されないまま同じ内容に二度ディスパッチされた席、三回目の
レビューラウンド、同一のブリーフ、そしてタスクの予算を超えたディスパッチを拒否します。メッセージは
台帳の行を引用します。それは障害ではなく答えです。記録された結果を使うか、何かを変えてゲートを一度
実行してください。上書きできるのはあなただけで、そのことは `.claude/hooks/README.md` に書かれています。
登録済みの `TASK-NNN` も、`TIER: direct` や `TIER: standard` の目印も示さない書き込み可能な席も
拒否されます。

## タスクボードの手編集が拒否される

`guard-board` は `docs/tasks/master-plan.md` のタスク行の編集をブロックします。タスクの状態は、ファイルの
`status:`、そのフォルダ、ボードの行にあり、`python .claude/scripts/task.py move TASK-NNN
<state>` が三つすべてを変更して行を読み戻します。Phases の表と、ボード周辺の文章の編集は引き続き
許可されます。

## ハーネスが整合していない

```bash
python .claude/scripts/harness-check.py
```

登録が実行するすべてのフックスクリプトが存在するか、コマンドや表が名指しするすべての席が存在するか、
ティア表が席と一致するか、引用されたすべてのルールが存在するか、席が挙げるすべてのスキルが
インストールされているかを検査します。各所見は file:line と修正方法を示します。

## 明らかに必要なファイルをエージェントが読めない

これは実際のバグでした。拒否ルールが `.env.example` に一致していたのです。すべてのブロックメッセージが
エージェントに読めと言っている、まさにそのファイルです。修正済みで、評価は現在、サンプルファイルの
読み取り、ローカルファイルの作成、そしてそれを読み込んだ状態での実行をカバーしています。

自分のハーネスで似たことに出会ったら、拒否リストに挙げるべきは `env` を含むすべてのファイル名ではなく、
**値を持つ**ファイルです。`.claude/settings.json` と `protect-secrets` フックを確認してください。

## Cursor や Codex でアダプタが何でも許可してしまう

セルフテストを実行します:

```bash
python harness-bootstrap/scripts/port.py --self-test
```

両方のフックの系統を検査し、さらに、合格するマシンでは隠れてしまう二つのことも検査します。アダプタが、
そのプラットフォームで使われ得るすべてのインタプリタ名を候補に挙げること、そして評価できない呼び出しを
**拒否**することです。実行できないガードは答えを知りません。そこで「許可」と答えることこそ、
アダプタが塞ぐために存在する穴です。

かつてアダプタは `powershell` という名前を直に埋め込んでいましたが、これは Windows にしか存在しません。
macOS と Linux ではバイナリは `pwsh` なので、移植されたハーネスはすべての呼び出しでトレースバックを
出し、ガードは一度も実行されませんでした。

## グラフやビューアが古いデータを表示する

`.claude/state/harness-graph.json` は、`.claude/` 配下の何かを編集したときに `graph-stale` フックが、
また `/harness-update` と `/harness-toggle` が再生成します。ドキュメントグラフは自動では再構築
されません。`/docs-graph` は要求に応じて孤立した ID を表示し、`/code-graph` は `graph-stale` が各ソース
編集を照合するモジュールマップを更新します。スクリプトによる書き込みはエディタのフックを発火させない
ので、これらのコマンドが自分で再生成します。

強制的に再生成するには:

```bash
python .claude/scripts/harness-graph.py     # または: harness-view scan .
```

## 公開されている数字がおかしく見える

おかしいのかもしれません。次を実行します:

```bash
python scripts/check_numbers.py
```

ドキュメント、スライド、クリップ、図に引用されているすべての数字を、スクリプトが実際に出力する値と
比較し、矛盾があれば非ゼロで終了します。このプロジェクトの数字は過去にずれたことがあります。あるクリップは、
評価が 107 に達したずっと後も「26 / 26」だと主張しており、スラッシュの前後の空白のせいでチェッカーから
隠れていました。ですから、ページとスクリプトが食い違っていたら、スクリプトを信じて issue を開いてください。

## スキャフォルドが CONFLICT を報告する

これはエラーではありません。`CONFLICT` は、ファイルが存在し、インストールされるはずの内容と異なる
ことを意味し、ブラウンフィールドの突き合わせの待ち行列です。一件ずつ手で解決します。自分のものを
残す、適応させる、新しいものを採る、あるいは差分をタスクとして登録する。スキャフォルダは、あなたが
書いたものを決して上書きも削除もしません。

## スキャフォルダが変数で非ゼロ終了する

未解決の `{{VAR}}` を見つけたということです。これは意図的です。変数の欠落は、誰も気づかない
ルールファイルにプレースホルダを紛れ込ませるのではなく、大きな音を立てて失敗します。`vars.json` で
変数を埋めて、再実行してください。

## それでも解決しない

`harness-view assess .` の出力と失敗したコマンドを添えて
[issue](https://github.com/nguyenhx2/agent-harness-bootstrap/issues) を開いてください。assess の出力は
ノードを名指しするので、多くの場合、再現手順がなくても問題の場所を特定するには十分です。
