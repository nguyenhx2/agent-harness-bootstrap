Maintain the documentation twin of `/code-graph`. The two graphs answer different questions and
neither substitutes for the other:

- **Code graph** (`/code-graph`): dependency - what breaks if I change this module.
- **Docs graph** (this command): traceability - which spec section, requirement, ADR, and task
  talk about the same thing, and which IDs are orphaned.

What exists after a build:

- `.claude/state/docs-graph.json` - machine-readable: every ID (FR-, NFR-, BR-, ADR-, TASK-, ...),
  the document that defines it, every document that references it, edge counts.
- `docs/context/docs-graph.md` - agent-readable mermaid graph plus the orphan-ID list.
- `docs/context/specs-graph.html` - self-contained interactive graph (open in any browser, no
  network needed). Regenerated by `graph-html.py` together with `harness-graph.html`.

Procedure:

1. Build: `python .claude/scripts/docs-graph.py`. Show the doc/ID/edge/orphan counts it prints.
2. Export HTML: `python .claude/scripts/graph-html.py`. (After the first build, the
   `graph-stale` hook re-runs both steps automatically on every `docs/**/*.md` edit, so a manual
   rebuild is only needed when the hook is disabled or the graph was never built.)
3. Report what CHANGED (`git diff docs/context/docs-graph.md`): a new orphan ID is unstarted work
   or a dead reference - name it and say which; an ID whose defining document moved usually means
   a requirement got rewritten in place - check the revision history caught it.

How agents use it:

- **spec-guardian** checks a diff's claimed requirement IDs against the graph: an implementation
  naming an FR the graph does not know is implementing an invented requirement.
- The **orchestrator** uses orphan IDs as a backlog signal: a requirement no task ever references
  is work nobody scheduled.
- **ba-analyst** runs `--check` after editing specs: exit 1 means the edit broke traceability.
