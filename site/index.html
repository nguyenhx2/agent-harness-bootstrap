§1

What it is

Three pieces that hand off to each other. You can use the first on its own; the second is where most of the value is; the third is how you check the second did what it said.

  • /spec-builder

    Skill

    Turns whatever you brought into one contract, written to international standards, that you and the AI both read from.

    • An idea, a transcript, legacy docs, a bare repo
    • Reads PDF / Office sources through a router that knows when a file cannot be read - unreadable never becomes a guess
    • ISO/IEC/IEEE 29148, ISO 25010, BABOK v3, C4, arc42
    • Stable IDs so every later change traces back

  • /harness-bootstrap

    Skill

    Builds the operating harness in your repo: who does what, at what cost, with what they are not allowed to do.

    • 16 agents, each with an explicit model and effort
    • 16 rules, 9 of them loaded only on the paths they govern
    • 10 blocking hooks, 22 commands, a task board that survives compaction

  • harness-view

    Tool

    Reads the harness as it actually is on disk and renders it. No model is involved, so a browser and a CI run cannot disagree about the answer.

    • Flow and graph views of every wire
    • A deterministic score, with each finding named
    • Toggle any rule, command or hook off and back on

How it all fits together

A loom is the honest picture. Threads go in tangled and cloth comes out, and nothing about that is magic: the frame is what makes the difference.

§3

Skill discovery and skill wire

Claude Code skills are only useful if the right ones are present and the right agent can reach them. Those are two separate problems, and the harness treats them separately.

  • Skill Discovery

    The problem it solves

    You should not have to know which skills exist, or go shopping for them. Discovery reads this project's manifests, works out its tech stack, and finds the skills that match it.

    • Python, Ruby, .NET, Java and Kotlin, JavaScript, plus monorepo markers
    • Marketplace catalogs are a source, not an authority
    • Nothing is installed unless you choose it

  • Skill Wire

    The problem it solves

    An installed skill that no agent is told to use is dead weight you still pay context for. Wiring connects a chosen skill to the agent seat that needs it, and records the connection.

    • The wire is a node in the graph, not a convention
    • harness-view shows which skills are wired and which are merely installed
    • An unwired skill is a finding, not a mystery

§4

See it, score it, switch it off

A harness you cannot inspect is a harness you are trusting on faith. harness-view renders the real thing from the state the run wrote, and every node is a file you can open.

§6

Install

Two paths. The plugin keeps itself up to date; the zip pins a version and works offline. Claude Code picks the skills up on the next session either way.

Install as a plugin

Recommended

Inside any Claude Code session:

/plugin marketplace add nguyenhx2/agent-harness-bootstrap
/plugin install harness-bootstrap@agent-harness-bootstrap
/plugin install spec-builder@agent-harness-bootstrap

Updates arrive with /plugin update when a release bumps the version - no re-download, no stale copy.

Or install from the release zip

Offline, pinned

Unzip into your skills directory:

# both skills
unzip agent-harness-bootstrap.zip -d ~/.claude/skills/

# then, in your repo
/harness-bootstrap     # build the harness
/spec-builder          # or start from the contract

Run the viewer

Optional

The viewer ships as a standalone binary for Windows, macOS and Linux, and also runs as a local web UI:

harness-view serve .    # browse the harness at localhost
harness-view assess .   # score it, exit non-zero on a failing gate

Both are attached to every release, with checksums and the eval and benchmark output captured for that exact version.
