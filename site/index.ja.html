助言ではなく、遮断するガードレール。

二つの Claude Code スキルと一つのビューア。一つはあなたと AI が共有できる仕様を書き、 一つはリポジトリに合わせたエージェント編成を組み立て、もう一つはその全体を可視化して任意の部分を 無効化できるようにします。

新規開発でも、既存コードベースでも、監査専用でも。安全性の下限はシェルスクリプトと 終了コードで担保されるため、モデルを入れ替えても動きません。

§1

三つの構成要素

互いに引き継ぎ合う三つの部品です。一つ目は単独でも使えます。価値の中心は二つ目にあり、 三つ目は二つ目が宣言どおりに動いたかを確認する手段です。

  • /spec-builder

    スキル

    持ち込まれたものを、あなたと AI の双方が読む一つの契約に変換します。記述は国際標準に沿います。

    • アイデア、議事録、既存ドキュメント、空のリポジトリ
    • PDF / Office ソースはルーターが読み方を判定 - 読めないファイルが推測になることはない
    • ISO/IEC/IEEE 29148、ISO 25010、BABOK v3、C4、arc42
    • 安定 ID により、後の変更がすべて遡れる

  • /harness-bootstrap

    スキル

    リポジトリに運用ハーネスを構築します。誰が何を、どれだけのコストで、何をしてはならないかを定めます。

    • 16 のエージェント、それぞれにモデルと推論強度を明示
    • 16 のルール、うち 9 は対象パスでのみ読み込み
    • 10 の遮断フック、22 のコマンド、コンパクションを越えるタスクボード

  • harness-view

    ツール

    ディスク上の実際のハーネスを読み取って描画します。モデルは介在しないため、ブラウザと CI の 結果が食い違うことはありません。

    • すべての配線を示すフロー表示とグラフ表示
    • 決定的な採点と、名指しされた検出結果
    • 任意のルール・コマンド・フックの有効と無効の切り替え

§2

全体像

織機はこの仕組みの正直な比喩です。糸はもつれたまま入り、布になって出てきます。 魔法ではなく、枠があるからそうなります。

§3

スキル探索とスキル配線

Claude Code のスキルは、適切なものが存在し、かつ適切なエージェントが到達できて初めて 役に立ちます。この二つは別々の問題であり、ハーネスも別々に扱います。

  • スキル探索

    解決する課題

    どんなスキルが存在するかを利用者が知っている必要はありません。探索はこのプロジェクトの マニフェストを読み、技術スタックを判定し、それに合うスキルを見つけます。

    • Python、Ruby、.NET、Java と Kotlin、JavaScript、モノレポの目印
    • マーケットプレイスのカタログは情報源であり、決定権は持たない
    • あなたが選ばない限り何もインストールされない

  • スキル配線

    解決する課題

    どのエージェントからも使われないスキルは、コンテキスト代だけ払う死荷重です。配線は選ばれた スキルを必要とするエージェントの席に接続し、その接続を記録します。

    • 配線は慣習ではなく、グラフ上のノード
    • harness-view が、配線済みか単にインストール済みかを表示
    • 未配線のスキルは謎ではなく、検出結果として名指しされる

§4

見る、採点する、無効にする

検査できないハーネスは、信用するしかないハーネスです。harness-view は 実行が書いた状態から実物を描画し、どのノードも開けるファイルです。

§5

形容詞ではなく、検証結果

ここにある数値はすべて、リポジトリ内のスクリプトから得られ、あなた自身が再実行できます。 モデルの所感は一つもありません。

  • 数値 何を測ったか 出どころ

  • 107/107

    ガードレール評価（フック形式ごと）。両形式で 214/214。

    遮断必須 40、許可必須 67

  • 0/22

    素のリポジトリが遮断できたペイロード数。ハーネス導入後は 22/22。

    benchmark/benchmark.py

  • 32/32

    Cursor と Codex への移植アダプタの自己テスト（両フック形式）。

    port.py --self-test

  • 64%

    ルールはパスでスコープされるため、既定セッションから外れるルール本文の割合。

    16 ルール中 9 がパススコープ

  • 7〜15

    16 席のうち、一回の実行で埋まる席数。契約と実在するモジュールから導かれ、既定ですべてが埋まることはありません。

    最小構成の回答なら 7 席

Opus を Haiku に入れ替えても、評価結果はバイト単位で同一です。 それがこの設計の要点で、下限はシェルスクリプトと終了コードによって強制されるため、どのモデルが 動かしているかに依存しません。安いモデルで変わるのは、書かれるコードの質とレビューの深さ、 すなわち上限であり、この評価はそれを測っていません。

§6

導入

経路は二つ。プラグインは自動で最新に追従し、zip はバージョンを固定して オフラインでも動きます。どちらでも、次のセッションから Claude Code がスキルを認識します。

プラグインとしてインストール

推奨

Claude Code のセッション内で:

/plugin marketplace add nguyenhx2/agent-harness-bootstrap
/plugin install harness-bootstrap@agent-harness-bootstrap
/plugin install spec-builder@agent-harness-bootstrap

リリースがバージョンを上げると /plugin update で更新が届きます - 再ダウンロードも古いコピーもなし。

または リリース zip からインストール

オフライン・固定

スキルディレクトリに展開するだけです:

# 両方のスキル
unzip agent-harness-bootstrap.zip -d ~/.claude/skills/

# そのうえで、対象リポジトリ内で
/harness-bootstrap     # ハーネスを構築する
/spec-builder          # あるいは契約から始める

ビューアを動かす

任意

ビューアは Windows・macOS・Linux 向けの単体バイナリとして配布され、 ローカルの Web UI としても動作します。

harness-view serve .    # localhost でハーネスを閲覧
harness-view assess .   # 採点し、基準を満たさなければ非ゼロ終了

いずれも 各リリース に添付されます。チェックサムと、そのバージョンで実際に取得した評価およびベンチマーク結果も同梱されます。
