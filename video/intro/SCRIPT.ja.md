# 00 intro (Japanese) - script and captions

The Japanese twin of `SCRIPT.md`: the narration, the burned-in captions and the scene cuts of
`video/mp4/ja/00-intro.mp4` all come from this file. The scene ids, the order and the claims are
the same as the English script; only the language differs. The format is the same: each `##`
heading is a scene, each `-` line under it is one caption cue, and the narration sent to the voice
is the cues joined with a space, so a caption can never say something the voice does not.

`scripts/build-timing.mjs ja` writes `src/timing.ja.json` from this file and the Japanese
narration's character alignment, and refuses to run when the two no longer match
(`bash render.sh --generate voice --force` regenerates both voices).

Each question scene opens with a short lead-in line, then the quoted question, then the answer;
the quote marks tell the composition which cue is the question. The narrator (Konoha) answers;
the question is heard in a second voice (Asahi), recorded on its own
(`audio/question.ja.<scene>.mp3`) and put in place of the narrator's reading of it. The question bubbles quote the
section headings of "解決する問題" in `README.ja.md`. The script is written shorter than a
translation would be, so the voice can speak at its own pace: nothing is sped up. The narration
speaks no count; the figures on screen are listed in the generated block at the bottom.

## open

- AIエージェントに、本当に理解できるリポジトリと、
- 抜け出せないハーネスを。

## frame

- 実務でエージェントを使うチームは、同じことを聞いてきます。
- その質問と答えを見ていきましょう。

## team

- まずはチーム。
- 「自分のプロジェクトに合ったエージェントチームがほしい」
- harness-bootstrap は、まずコードを読んで、目的を聞きます。
- 開発担当はモジュールごとに一人。全員は入れません。
- スタックに合うスキルを探して、それぞれを必要な担当につなぎます。

## safe

- 次は、安全とコスト。
- 「安全にしたい。でも考えすぎやトークンの浪費は困る」
- フックはシェルで止めるので、モデルは判定しません。
- main への強制プッシュも、最初から拒否。

## lean

- verify-plan は差分を見て、必要な検証だけを求めます。
- 合格済みの再レビューは台帳が断り、回数にも上限があります。
- モデル、effort、ツールは、エージェントごとに固定。

## keys

- 続いて、秘密情報。
- 「キーの漏洩が心配」
- protect-secrets が、env ファイルや鍵の読み取りを止めます。
- env-read は値を使って実行し、出力では伏せます。

## loop

- 次は、仕事の進め方。
- 「従来の SDLC ではタスクごとに苦労し、AI-DLC は中途半端に終わる」
- 仕様が判定基準の、一つのループ。要件、タスク、実装、検証、レビュー、完了。
- 小さな編集はその場で、スキーマ変更はガード付きで。

## spec

- そして、仕様。
- 「人が確認でき、AI が理解できる仕様がほしい」
- spec-builder は、顧客向けの確認シートと、エージェントが最初に読むインデックスを作ります。
- 分からないことは、作らずに明示します。

## control

- 次は、中を見ること。
- 「エージェントがどう動いているのか、全体も細部も理解して制御したい」
- harness-view は、エージェントもルールもフックも、ライブのグラフにします。
- どの部品も安全にオフにでき、実行はすべて記録されます。

## assess

- 最後は、確認。
- 「出来上がったハーネスは確認しきれず、直すのも遅い。採点基準も曖昧」
- harness-view assess は、それを作業リストに変えます。ワンクリック修正つきです。
- 指摘には、ルール ID、ファイルと行、直し方。採点表は公開済みです。

## close

- 本当に理解できるリポジトリと、抜け出せないハーネス。
